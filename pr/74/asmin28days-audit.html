TI-84 Plus OS — Reverse Engineering

ASMin28Days source audit

ASMin28Days Version 2.0 is a TI-83 Plus assembly course published in 2004. This audit separates its Z80 lessons, historical TI-83 Plus conventions, and claims that apply to TI-84 Plus OS 2.55MP. It also records the claims checked against the target ROM and a pinned TilEm run.

Source identity

The audited source is the live ASMin28Days table of contents. The complete authored mirror contains 92 files and has archive SHA-256 be525f651b940443e874b9f630e07e25353ddae34772d17e3908a1cda7816a99. It includes every file in the known Version 2.0 distribution plus the live favicon. The source record in tools/asmin28days-claims.json binds the table of contents and all 28 lesson pages reviewed below. [confirmed]

The maintained Version 3 source is a separate edition. Its existence does not change the Version 2.0 byte record or the target-ROM results on this page.

Source integrity

The table-of-contents crawl reaches 82 authored files. The known Version 2.0 source tree contains 91 files; all 91 remain available, including ten files that the live link graph does not reach. The live favicon makes the complete mirror 92 files and 1,260,127 bytes. Directory indexing is disabled, so this coverage is complete relative to both the reachable graph and the known Version 2.0 tree. [confirmed]

The live copy has three broken relative-link patterns: Day 9 points to z80is.html instead of ../ref/z80is.html, Day 20 points to day19html instead of day19.html, and ref/direct.html points to day03.html instead of ../lesson/day03.html. Day 15 also targets a missing Day 8 bol fragment. Day 16 and ref/direct.html define several anchor names with a literal leading #, so the intended fragments do not resolve. [confirmed]

The host copy contains six replacement characters where the Version 2.0 source has four middle dots on Day 5 and multiplication and division signs on Day 27. The audit evaluates the intended characters from the versioned source when those examples depend on the corrupted symbols. [confirmed]

Matrix storage correction

ASMin28Days Day 19 gives the matrix header as columns followed by rows and stores elements row-major. The target ROM agrees. _CreateRMat receives H=rows and L=columns; the common writer at ram:10EE stores L before H. _AdrMEle at 02:4002 takes B=row and C=column and computes:

$$ ((\mathit{row}-1)\cdot\mathit{columns}+(\mathit{column}-1))\cdot 9 $$

The dynamic witness uses header bytes 03 02. It records offsets 2, 20, 29, and 47 for (1,1), (1,3), (2,1), and (2,3). _AdrMRow returns offset 29 for row 2. These offsets include the two-byte header. [confirmed]

Day 5 presents its generic row-major and column-major formulas in the opposite order. Day 19 supplies the correct TI matrix representation. The formulas are therefore assessed separately rather than treating the tutorial as internally consistent.

Symbol lookup qualification

The TI SDK recommends _ChkFindSym for Programs and AppVars. OS 2.55MP keeps that public distinction but implements overlapping internal capability. _ChkFindSym at 00:0E60 recognizes the five named classes at ram:2042 and routes them to the length-prefixed scanner at 07:55D1. _FindSym at 00:0E65 reaches findsym_scan at 07:565F, whose name classifier can also select 07:55D1. [confirmed]

The SDK recommendation is valid API guidance. It is not evidence that this ROM’s _FindSym body cannot process a correctly formed length-prefixed OP1.

LCD qualification

ASMin28Days Day 26 correctly separates command port 0x10 from data port 0x11. It sends contrast as a 0xC0–0xFF command. The target ROM’s lcd_write_data at 01:5A59 and lcd_read_data at 01:5A60 use port 0x11 for pixel data; they are not contrast helpers. _LCD_DRIVERON builds the contrast command from the OS byte at 0x8447. [confirmed]

Day 26 describes the Toshiba T6A04. That controller’s commands and dummy-read pipeline are useful historical evidence. Controller identity, hidden width, busy duration, and out-of-range aliases vary across TI-84 Plus revisions and remain separate hardware questions.

Reproduction

Validate the source mirror and ROM anchors:

nix develop -c python tools/asmin28days_claims.py \
  --rom tools/rom.bin \
  --tutorial-root "$TUTORIAL_ROOT" \
  --output /tmp/asmin28days-claims.json

Run the matrix witness through the pinned headless TilEm build:

nix develop -c python tools/run_asmin28days_matrix_probe.py \
  --rom tools/rom.bin \
  --tilem "$TILEM" \
  --output /tmp/asmin28days-matrix

The runner checks the ROM and emulator hashes, builds the payload with SPASM-ng, transfers it through the OS link receiver, executes it through Asm(, resolves the full trace, and checks the logical-RAM result. Raw traces and the proprietary ROM remain outside Git. The reduced fixture retains their hashes.
